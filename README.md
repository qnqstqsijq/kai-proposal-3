# Kai website (Proposal 3)

The Kai marketing website: the approved homepage with its 3D particle header, plus every other page from the sitemap, built from the Kai content docs.

- **Latest live version:** https://kai-proposal-3-phi.vercel.app
- **Content docs (Google Drive):** https://drive.google.com/drive/folders/1n7gxN3NTEIG525LoAG7Q5HYLMck64as3
- **What it is:** a plain static site. No npm install and no framework. Python 3 (preinstalled on macOS) serves it and builds the pages.
- **Internet needed:** the homepage loads Three.js and Lenis from the jsDelivr CDN, and the other pages load Lenis from it too. Everything else is in the folder.

---

## 1. Run it locally

The site **must be served over http**. Double-clicking `index.html` (`file://`) does not work: the browser blocks the scripts and videos.

Open a terminal in this folder (the one that contains `index.html`) and run:

```bash
python3 -m http.server 5192
```

Then open **http://localhost:5192** in Chrome.

- The homepage takes a few seconds on first load: the particle landscape is generated in the browser. A small loader shows meanwhile.
- The Python server lets the browser cache pages. After a change, reload with **Cmd+Shift+R** (Ctrl+Shift+R on Windows) or you may see the old version.
- Stop the server with Ctrl+C.

## 3. How the site is built

There are two kinds of pages.

**The homepage (`index.html`)** is hand-built and self-contained: all of its CSS and most of its JavaScript are inside the file, and some images are inlined. Edit it directly, carefully. The build script only reads it (to reuse the logo, footer wordmark and app badges) and never writes it.

**Every other page** is generated by a small Python script:

```bash
python3 src/build.py
```

It writes each page to its address as a folder, for example `/personal/accounts/` becomes `personal/accounts/index.html`, plus `404.html`. It prints how many pages it built (65 today). Run it after every change in `src/` or `assets/site/`; it updates the cache-busting version on the CSS and JS links automatically.

### How the homepage header works (`assets/phero.js`)

The header is driven by scroll in two phases:

- **`window.__PRE` (0 → 1)** is the first chapter, set by `frame()` in `index.html`. It spans 3 screen heights of scroll.
  - `0 – .34`: the landscape sinks away and the dust forms the **globe with the Kai icon** (`uForm`).
  - `.36 – .58`: the globe passes through the violet orb into the **speech bubble** (`uMerge`, `uBub`).
  - `.60+`: the HTML bubble `#bub` fades in and its text types (`.64 – .86`).
- **`P` (0 → 324)** is the page's header timeline after that. It brings in the UI card (`#panel`) and so on. See `scene1()` in `index.html`.

| What | Where to look in `phero.js` |
|---|---|
| Terrain shape / mountains | `heights` (top of file, `T_SIZE`, `T_N`) |
| Stage timings | lines with `ss(.02,.34,pre)` / `ss(.36,.58,pre)` |
| Globe icon colour | `vec3 C1=tk>.5?vec3(.42,.74,.76)…` |
| Always-on floating dust | the "screen dust" layer (`N = 11000` desktop / `4500` mobile) |
| Dust circling the globe / bubble | the "orbit dust" layer (`9000` / `3500`, radius `R=15`) |
| Mountains hiding the dust | `depthMesh` (depth-only occluder) |
| Headline fade-in | `window.__txtShow` and the h1/h2 hook |

**Bump the cache-buster after every edit to `phero.js`.** It's loaded as `<script type="module" src="assets/phero.js?v=78">` near the bottom of `index.html`; change `v=78` to `v=79` and so on.

The homepage's menu, dropdowns, footer and buttons were linked to the other pages by hand (buttons use `data-href`). If the sitemap changes, update the homepage's header and footer in `index.html` too; the build does not touch it.

## 4. Changing content

### Where the copy comes from

Each page has a Google Doc in the Drive folder above, named by its code (H-01 Home, P-02 Accounts, B-09 Business pricing, ...). In every doc, **text in blue is the copy that appears on the website**; everything else is notes and tasks. The docs are drafts (v0.1 to v0.7) and still need Team, Compliance and SEO approval, so expect changes.

To read a doc's copy quickly, open `https://docs.google.com/document/d/<doc id>/mobilebasic`: the website copy is in spans styled `color:#0b57d0`. Page titles and descriptions come from each doc's "Meta and OG" section.

### Editing a page

Find the page by its code in the `src/pages*.py` files. A page is a list of sections, for example:

```python
dict(t="hero", variant="sub", eyebrow="Accounts", h1="Your own IBANs in euros and pounds",
     sub="Receive, hold and send EUR and GBP ...", buttons=[WAIT], visual="accounts"),
dict(t="flist", h2="What you can do", rows=[("globe", "Your own IBANs.", "Personal virtual IBANs ..."), ...]),
dict(t="faq", h2="FAQ", items=[("Which currencies can I hold?", "We start with EUR and GBP ..."), ...]),
dict(t="final", **FINAL),
```

Change the text, save, run `python3 src/build.py`, reload the page.

### Shared with the homepage (added 24 Nov)

- **FAQ** uses the homepage's markup, spacing and behaviour: first item open, one open at a time, opens on hover on desktop.
- **Cards and tiles** (`cards`, `tiles`) copy the homepage product cards (432:350, 3D scene on hover, icon and text lift). The build copies the homepage's 3D hover module into `assets/site/cards3d.js` (generated, don't edit) and gives each card a `data-scene` from its title (`pick_scenes` in `build.py`).
- **Header:** transparent at the top of every generated page; frosted once you scroll (`is-clear`, as on the homepage).
- **Placeholder imagery:** every photo from `assets/media/` and `assets/site/img/` is swapped for the cubes video (`assets/kai-cubes-h264.mp4`) at build time (`cubes()` in `build.py`). Portraits are kept. Remove the `cubes()` call in `write()` when final imagery arrives.
- **UI screens** use the homepage UI tokens (frosted window, translucent inner boxes, pills, teal check for finished steps, nothing fully opaque) and its motion (dividers draw, values fade, Confirm fills). Every frame has the cubes video and the panel sits in the corner.
- **No small titles (eyebrows)** above headings, and section call-to-action links render as the main button (`btn1`).

### Section types (all in `src/build.py`)

| `t=` | What it renders |
|---|---|
| `hero` | Page header. `variant`: `main` (overview pages), `sub` (subpages), `text` (no visual). Optional `buttons`, `line`, `visual` |
| `tiles` | Linked tiles with icons (Personal overview) |
| `flist` | Heading on the left, rows with icon, label and text on the right |
| `split` | Text beside an illustrative visual; `rev=True` mirrors it |
| `cards` | Grid of cards (2 to 5 columns, optional icon and link); `feat=True` for the compact 10-feature grid; `dark=True` puts it in a dark panel |
| `steps` | Numbered steps (only for real sequences) |
| `text` | Statement: headline left, text right; `dark=True` for a dark panel |
| `checks` | Checklist rows |
| `table` | Fee table with Silver, Gold and Platinum columns |
| `plans` | Three plan cards |
| `compare` | Two-column comparison (Why Kai) |
| `facts` | Key and value rows (Kai facts, company details) |
| `people` | Team cards linking to profile pages |
| `form` | Contact form (`kind="contact"`) or contact sales form (`kind="sales"`) |
| `roles` | Open roles (Careers) |
| `stories` | Customer stories (samples from the homepage) |
| `boiler` | Press boilerplate box |
| `band` | Small band with a button (the Fees link) |
| `faq` | FAQ accordion in the homepage style |
| `promos` | One full section per linked page, built from that page's own hero (used instead of "Next" links on Personal pages) |
| `next` | Row of link blocks ("Your path", "Explore") |
| `cards2` | Two large photo cards (Made for you) |
| `final` | The closing dark "Become the First" section |

Text pages (Trust, Compliance) use `template="doc"`; Blog, News and Press use `template="listing"`; the Resources hub uses `template="hub"`; the Glossary uses `template="glossary"`.

### Illustrative screens

Product screens are built in code from data, never invented as images. A `visual=dict(...)` can have a `photo`, `title`, `chip`, `total`, `rows`, `kv` (key/value box), `msgs` (agent chat), `card` (virtual card), `steps`, `acts` (action buttons), `btn`, or `kind="layers"` for the layer diagram. Screens carry no "Illustrative" label. Their frames (`.stage`) are one size everywhere (16:13), and go full width below 1280px so the panel always fits.

### Pages without content, and TBC items

- Pages with no content doc yet are set to `missing=True` in `src/sitemap.py` (Supported assets, Solutions, Treasury, Help / FAQ, Privacy Policy, Terms of Use, Cookie Policy, Search results). They show as "(no-content)" in the menus and footer and are not linked. When a doc arrives: set `missing=False`, add the page to a `src/pages*.py` file, rebuild, and link it on the homepage by hand.
- Copy marked TBC in the docs shows in grey italic (press email, careers email, phone, founding year, cookie banner text, consent wording, country list, form response times).

### Adding a new page

1. Add it to `src/sitemap.py` (code, name, address).
2. Add its content to the right `src/pages*.py` file under the same code, with `level` (see below), `title` and `desc` from the doc's "Meta and OG".
3. Run `python3 src/build.py`. The menus, footer and sitemap page update automatically on every generated page.
4. If it belongs in the homepage menu or footer, add the link in `index.html` by hand.

## 5. Design rules

- **Design language:** everything follows the homepage: the same colour tokens, Clash Display headlines, Clash Grotesk body, 12-column grid, button hover, glass cards, FAQ and footer. `kai.css` starts with the homepage's tokens and scales with the window above 1200px, as the homepage does.
- **Animation levels** (set per page with `level`):
  1. Homepage: the heavy, scroll-driven particle header (untouched).
  2. Overview pages (Personal, Business, How Kai Works): interface panels that count and convert as you scroll, smooth scrolling, drifting background.
  3. Subpages, Pricing, Why Kai and Company pages: sections fade up as they appear.
  4. Resources, Trust, Compliance and utility pages: static, only hover effects.

  All motion switches off for visitors who choose reduced motion.
- **Responsive:** every generated page works at phone, tablet and desktop widths with no sideways scrolling. The menu becomes a full-width panel at 1024px and below. The homepage has no mobile viewport setting (as approved), so phones show it at about 980px wide.
- **Pop-ups:** "Become the First" and "Join Waitlist" open the waitlist pop-up (S-03) on generated pages; the homepage's buttons go to the `/waitlist/` page. Forms check required fields and show the S-05 confirmation, but **nothing is sent anywhere yet**: there is no backend.
- **Cookies:** the banner (S-04) shows on a visitor's first visit to any generated page and remembers the choice in the browser. The homepage has no banner yet.

## 8. Troubleshooting

- **"Operation not permitted" when Claude starts the preview:** macOS is blocking access to `Documents` or `Desktop`. Move the folder elsewhere (e.g. `~/Projects`), or start the server yourself with `python3 -m http.server 5192` in a terminal and let Claude attach to http://localhost:5192.
- **A page looks out of date:** hard-reload with Cmd+Shift+R; the local server lets the browser cache pages.
- **Port 5192 is in use:** run the server on another port, e.g. `python3 -m http.server 5200`, and open that port instead.
- **The build fails:** it prints the Python error with the file and line. Most often it's a missing comma or quote in a `src/pages*.py` file.
